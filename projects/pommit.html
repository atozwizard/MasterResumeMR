01. POMMIT

NLP 전처리의 시작점과 HybridRAG 확장 방향 검토

해커톤 기반 팀 POMMIT에서 company_analyzer의 기업 분석 축을 맡아, service_agent 최소기능과 운영 문서를 정리하고 NLP 전처리에서 HybridRAG 방향까지 이어지는 다음 단계를 검토한 협업 프로젝트입니다.

핵심 메시지

이 프로젝트에서 저는 협업 경험을 쌓은 사람이 아니라, 여러 에이전트가 얽힌 프로젝트에서 흐름과 기준을 먼저 세우고 NLP 처리 방향까지 정리하는 사람으로 기여했습니다.

내 역할

  • service_agent 최소기능 방향 설계와 구현 정리
  • HTML 정리 → 텍스트 정제 → 단어 빈도 추출 → collector 전달 흐름 구체화
  • 상태 스키마, 문서 구조, 마일스톤 운영 기준 정리
  • HybridRAG, NLP 전처리, sparse data 보강 방향 검토 및 문서화

왜 이 프로젝트가 중요했는가

company_analyzer는 GitHub, JD, 기술 블로그, 서비스 설명문을 함께 다루는 구조라서, 기능을 빨리 붙이는 것만으로는 앞으로 나가지 않았습니다. 각 에이전트가 무엇을 받고 무엇을 넘기는지, 어떤 산출물을 남기는지, 팀이 어떤 기준으로 작업을 관리할지가 먼저 잡혀야 했고, 서비스 설명문에서 요구역량을 어떻게 추출할지도 함께 정리돼야 했습니다.

  • 구현은 늘어나도 입출력 계약이 맞지 않으면 다음 단계로 연결되지 않습니다.
  • 협업 기준이 흔들리면 팀 산출물이 약해집니다.
  • 서비스 설명문 처리도 임시 로직에 머물러 이후 HybridRAG 확장으로 이어지기 어렵습니다.

실제로 무엇을 했는가

  • company/service_agent를 기준으로 서비스 설명문 처리 축을 정리했습니다.
  • html_cleanup_node.py에서 HTML 태그를 걷어내고 의미 있는 텍스트만 남기는 흐름을 잡았습니다.
  • word_frequency_node.py에서 정리된 문서를 받아 불용어를 제거하고 단어 빈도를 세어 service_evidences 형태로 collector가 받을 수 있게 만들었습니다.
  • ServiceAgentState에 cleaned_documents, service_word_frequencies 같은 필드를 두고, 파일 저장보다 객체 전달이 우선되도록 상태 흐름을 정리했습니다.
  • plan-service-collector-mvp, 마일스톤 운영 가이드, 프로젝트 루트 구조 가이드를 정리해 팀이 같은 기준으로 움직이게 했습니다.

NLP 전처리 관점

서비스 설명문에서 요구역량을 뽑아내려면 원문 HTML을 그대로 넘기는 것보다 먼저 문서 노이즈를 제거하고, 의미 있는 텍스트만 남기고, 최소 단위의 단어 신호를 정리해야 합니다. 저는 이 출발점을 service_agent 안에 두었습니다.

  1. 서비스 설명문 HTML을 읽습니다.
  2. script, style, 태그를 제거해 텍스트만 남깁니다.
  3. 정리된 텍스트를 cleaned_documents에 객체 형태로 담습니다.
  4. 텍스트에서 불용어를 제외하고 단어 빈도를 계산합니다.
  5. 결과를 service_word_frequencies와 service_evidences로 만들어 collector가 이어서 합칠 수 있게 넘깁니다.

현재 구현은 형태소 분석 전체가 아니라 전처리와 근거 신호 정리의 시작점이며, 이 단계가 있어야 이후 형태소 분석기 도입이나 HybridRAG가 설명 가능한 구조로 붙습니다.

왜 HybridRAG를 봤는가

서비스 설명문에서 중요한 요구역량은 적게 등장할 수도 있고, 서로 떨어져 있는 문장 관계 안에서 의미가 생길 수도 있습니다. 단순 빈도만으로는 이런 맥락을 복원하기 어렵습니다. 그래서 이후 단계로 HybridRAG, NLP 전처리 강화, sparse data 보강을 검토했습니다.

결과와 의미

service_agent와 collector_agent를 잇는 단어 빈도 최소기능이 반영됐고, 상태 스키마와 객체 전달 흐름이 정리되면서 이후 에이전트 연결을 더 설명 가능하게 다룰 수 있는 기반이 생겼습니다. 이 프로젝트는 복잡한 에이전트 프로젝트 안에서 구조를 먼저 세우고 NLP 처리 방향과 다음 실험 방향까지 정리하는 사람이라는 점을 보여줍니다.

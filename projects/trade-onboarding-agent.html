03. trade-onboarding-agent

RAG와 riskmanaging agent를 중심으로 다룬 무역 온보딩 미니프로젝트

무역 실무 온보딩을 위해 RAG 기반 지식 검색과 riskmanaging agent를 중심으로 구성한 멀티에이전트 미니프로젝트입니다.

핵심 메시지

이 프로젝트에서 제가 중심으로 다룬 것은 오케스트레이터 전체보다, 무역 도메인 RAG와 riskmanaging 흐름이 실제로 작동하도록 만드는 부분이었습니다.

왜 필요했는가

신입사원 온보딩은 문서만 많이 보여준다고 해결되지 않았습니다. 사용자는 용어 이해, 이메일 작성, 리스크 판단처럼 다른 성격의 작업을 연속으로 수행해야 했고, 그 과정에서 앞선 대화 맥락이 계속 이어져야 했습니다.

내 역할

  • 무역 도메인 데이터 기반 RAG 구조 확인 및 정리
  • riskmanaging agent 흐름과 관련 문서, 데이터, 처리 구조 파악
  • 프로젝트 저장소 기준으로 백엔드 구조와 API 흐름 정리

어떻게 작동하는가

  1. 무역 도메인 데이터셋을 정리하고 ingest.py를 통해 ChromaDB에 임베딩 기반 검색 자산을 만듭니다.
  2. 사용자가 리스크 관련 질문을 보내면 riskmanaging agent가 필요한 정보를 대화형으로 수집합니다.
  3. RAG 검색으로 관련 무역 문서를 찾고, 이를 바탕으로 리스크를 평가합니다.
  4. 최종적으로 리포트 형태의 결과를 반환합니다.
flowchart LR A[무역 도메인 데이터셋] --> B[ingest.py] B --> C[ChromaDB] D[사용자 입력] --> E[riskmanaging agent] E --> F[대화형 정보 수집] F --> G[RAG 검색] C --> G G --> H[리스크 평가] H --> I[보고서 / 응답 반환]

근거와 산출물

  • RAG 자산: dataset/*.json, ingestable 기준 지식 베이스 정리 흔적
  • RiskManaging 관련 문서: docs/riskmanaging_workflow.md, docs/riskmanaging_agent_REPORT.md
  • 프로젝트 구조 문서: README.md, CLAUDE.md
  • 백엔드 자산: backend/rag/*, backend/agents/riskmanaging/*, risk_checkpoints.db

결과와 의미

이 프로젝트는 단순 용어 검색이 아니라, 리스크 질문을 대화형으로 수집하고 RAG 근거를 붙여 응답하는 흐름을 다룬 프로젝트입니다. 저는 오케스트레이터 전체를 과장해 설명하기보다, 무역 도메인 RAG와 riskmanaging 흐름이 실제로 어떻게 돌아가는지 중심으로 작업하고 정리했습니다.

04. poketdogam

OCR, 후보 확인, fallback, trace를 담은 멀티모달 흐름

텍스트 질의와 이미지 스캔이 하나의 제품 경험으로 이어지도록 설계한 멀티모달 도감형 AI 서비스 프로젝트입니다.

핵심 메시지

이 프로젝트의 중심은 기능 나열이 아니라, 스캔 실패까지 포함해 사용자 경험이 끊기지 않는 흐름을 만드는 일이었습니다.

왜 필요했는가

사용자가 정보를 찾는 흐름은 보통 검색, 이미지 확인, 상세 조회가 따로 놀기 쉽습니다. 특히 이미지 입력은 OCR 실패, 후보 매핑, 모델 오류 대응까지 함께 고려해야 실제 서비스로 이어질 수 있습니다.

무엇을 구현했는가

  • FastAPI 라우트: chat, scan, pokedex
  • PokedexAgentGraph 기준 처리 흐름
  • 입력 수집, OCR, 후보 확인, 문맥 검색, 응답 생성, trace 저장 구조
  • 설계 문서 기준 기술 조합: LiteLLM, Upstage OCR, Supabase pgvector, Graph DB, Langfuse

실패를 어떻게 다뤘는가

이미지를 받으면 OCR을 실행하고, 결과가 확실하면 문맥 검색으로 넘깁니다. 애매하면 후보 확인 단계로 보내고, 그래도 불확실하면 fallback 경로로 넘긴 뒤 최종 응답과 trace를 남깁니다. 이 프로젝트의 강점은 OCR을 붙였다는 사실보다 실패를 전제로 사용자 흐름을 설계했다는 점입니다.

구현된 것과 남은 것

현재 설명 가능한 것은 라우트 분리 구조, 멀티모달 사용자 흐름, OCR fallback 방향, trace와 observability 고려 구조입니다. 반면 실제 외부 연동 완성도, OCR 품질, GraphRAG 성능 검증은 이후 보강이 필요한 영역입니다. 이 구분을 분명히 두는 것이 이 프로젝트의 신뢰를 높입니다.

결과와 의미

단순 검색 데모가 아니라 제품 경험 중심의 멀티모달 AI 구조를 만들었고, AI 기능을 사용자 경험으로 번역하는 프로젝트로 설명할 수 있게 됐습니다. 이 프로젝트는 실패해도 사용자 경험이 끊기지 않는 멀티모달 흐름을 먼저 만들었다는 점을 보여줍니다.

# 프로젝트_문제해결_서비스보고서

## 프로젝트명
`job-analyzer`

## 한 줄 요약
채용 공고와 GitHub 저장소를 함께 분석해, 코드 경험을 기술 스택 나열이 아니라 비즈니스 가치와 역할 언어로 번역하는 AI 분석 프로젝트.

## 1. problem solve 관점

### 어떤 문제를 다루는가
- 일반적인 저장소 분석은 사용 기술 목록만 뽑아내고 끝나는 경우가 많아, `이 코드가 어떤 문제를 해결하는지`까지 설명하지 못한다.
- 채용 공고 역시 키워드 중심으로 읽으면 기업이 원하는 실제 역할과 업무 맥락을 놓치기 쉽다.
- 따라서 `저장소 구조`, `핵심 로직`, `기업 요구 역량`을 함께 읽어야만 의미 있는 적합도 분석이 가능하다.

### 왜 이 문제를 이런 방식으로 풀어야 했는가
- 단순한 문자열 매칭으로는 코드의 역할과 비즈니스 가치를 설명하기 어렵다.
- 반대로 LLM만으로 전체 저장소를 읽히면 토큰 낭비가 크고, 분석 근거가 흐려질 수 있다.
- 그래서 먼저 AST 기반으로 구조를 읽고, 그 다음 임베딩 기반으로 중요한 코드 조각을 좁혀 읽는 `structure-first + semantic zoom-in` 방식이 필요했다.

### 어떻게 구현했는가
- `Python AST`를 이용해 함수, 클래스, 시그니처를 먼저 파악하고 저장소 구조를 정리했다.
- `Solar Embeddings`를 활용해 기업 맥락과 가까운 코드 조각을 골라냈다.
- `LangGraph`와 `LangChain`을 기반으로 기업 분석, 저장소 분석, 리포트 작성 흐름을 순차 에이전트 구조로 연결했다.
- 스크래핑 단계에서는 가벼운 수집 실패 시 `Selenium` 기반 fallback으로 전환하는 구조를 사용해 외부 정보 수집 안정성을 높였다.

### 무엇이 핵심 결과인가
- 저장소 분석을 단순 기술 나열이 아니라 `코드 구조 + 역할 + 업무 가치` 언어로 해석할 수 있는 기반을 만들었다.
- AST와 임베딩을 결합한 방식으로, 구조적 분석과 의미적 분석을 동시에 가져가는 분석 흐름을 설계했다.
- 채용 공고와 저장소를 연결해 `이 프로젝트가 실제 어떤 비즈니스 가치에 기여하는가`를 설명할 수 있는 프로젝트가 되었다.

## 2. project service 관점

### 이 프로젝트는 어떤 서비스인가
- 지원자 관점에서는 자신의 저장소를 직무 언어로 해석해 주는 `포지셔닝 분석 서비스`다.
- 기업 관점에서는 코드와 JD를 연결해 기술 경험의 적합성을 읽어내는 `설명형 평가 서비스`다.

### 사용자에게 주는 가치
- 사용자는 자기 저장소를 `사용한 기술`보다 `해결한 문제`와 `역할` 중심으로 정리할 수 있다.
- JD와 저장소가 연결되므로, 이력서와 포트폴리오에 쓸 표현을 더 직접적으로 만들 수 있다.
- 분석 결과가 리포트 형태로 정리되기 때문에, 자기소개서와 면접 답변 재료로 재활용하기 좋다.

### 서비스 구조상 중요한 포인트
- 스크래핑, 코드 구조 분석, 의미적 매핑, 리포트 작성이 분리되어 있어 유지보수와 확장이 용이하다.
- 코드 전체를 무작정 읽는 대신 핵심 구조를 먼저 좁히는 접근이라 비용과 설명 가능성을 함께 관리할 수 있다.
- fallback scraping을 포함해 외부 소스 접근 실패에 대한 대비가 되어 있다.

## 3. 리줌에서 말할 수 있는 포인트
- Python AST와 임베딩 기반 유사도 계산을 결합해 저장소 구조와 역할을 함께 해석하는 분석 프로젝트 구현
- JD와 GitHub 저장소를 연결해 기술 경험을 업무 가치 언어로 번역하는 AI 분석 흐름 설계
- 구조 우선 분석과 fallback scraping을 결합해 설명 가능성과 수집 안정성을 함께 확보

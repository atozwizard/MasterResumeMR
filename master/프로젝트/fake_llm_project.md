# 프로젝트 문제해결 서비스보고서

## 프로젝트명
`fake_llm_project`

## 한 줄 요약
실제 모델 연동 전 단계에서, 에이전트 로직과 실행 흐름을 최소 구조로 분리해 본 개념 스케치형 LLM 실습 저장소.

## 1. problem solve 관점

### 어떤 문제를 풀려 했는가
- LLM 애플리케이션을 처음 다룰 때는 실제 모델 연동보다 먼저 `에이전트`, `도구`, `워크플로우`, `실행 코드`가 어떻게 나뉘는지 이해할 필요가 있다.
- 바로 복잡한 프레임워크를 쓰면 구조 감각을 잡기 어렵다.

### 왜 이 방식으로 풀었는가
- `agent.py`, `tools.py`, `workflow.py`, `main.py`처럼 파일을 단순 분리하면 역할 분담의 기본 개념을 빠르게 이해할 수 있다.
- 응답 자체는 mock으로 두고 구조만 먼저 나누는 편이 학습 진입 장벽을 낮춘다.

### 어떻게 구현했는가
- `LlmAgent.handle(user, message)` 형태의 최소 에이전트 인터페이스를 만들었다.
- 실행 진입점과 도구/워크플로우 파일을 분리했다.
- 실제 모델 API 없이도 메시지 흐름을 테스트할 수 있게 구성했다.

## 2. project service 관점

### 서비스라기보다 무엇인가
- 이 저장소는 서비스 프로젝트가 아니라 `LLM 앱 구조 개념 학습용` 저장소다.
- 배포형 제품보다는 에이전트 구조를 이해하기 위한 최소 샘플에 가깝다.

### 리줌 관점 의미
- 에이전트 구조에 대한 초기 이해
- 모듈 분리 감각
- 추후 확장 가능한 최소 스캐폴드 설계 경험

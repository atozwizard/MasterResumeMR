# 프로젝트 문제해결 서비스보고서

## 프로젝트명
`news_chatbot_agent_student`

## 한 줄 요약
뉴스 아카이브 검색, 실시간 뉴스 검색, 날짜 계산, 평가-개선 루프를 결합해 `교육용이지만 서비스형 구조를 갖춘 뉴스 챗봇 에이전트`를 구현한 프로젝트.

## 1. problem solve 관점

### 어떤 문제를 풀려 했는가
- 뉴스 챗봇은 단순 질의응답만으로는 부족하고, 과거 뉴스 아카이브와 최신 뉴스 검색을 함께 다뤄야 한다.
- 사용자는 `7일 전`, `이번 주` 같은 상대적 표현을 많이 사용하기 때문에, 검색 전 날짜 범위를 구조화해야 한다.
- 한 번 생성한 응답이 항상 충분히 좋지 않기 때문에, 평가 후 개선하는 루프가 필요하다.

### 왜 이 방식으로 풀었는가
- 검색과 응답 생성을 섞지 않고, 의도 분류 -> 선호도 추출 -> 계획 -> 도구 호출 -> 응답 합성 -> 평가 -> 개선 순서로 나눠야 각 단계 문제를 이해하기 쉽다.
- 뉴스 질의는 `실시간성`, `맥락`, `정확성`이 중요하므로 RAG, 외부 뉴스 API, 날짜 계산 도구를 함께 써야 한다.
- 교육용 프로젝트라도 evaluator-optimizer 패턴을 넣어야 `생성 -> 검증 -> 재생성` 구조를 학습할 수 있다.

### 어떻게 구현했는가
- LangGraph로 8개 노드(`classify_intent`, `extract_preferences`, `plan`, `research`, `synthesize`, `evaluate`, `improve`, `save_memory`)를 연결했다.
- `search_news_archive`, `calculate_date_range`, `search_recent_news` 3종 도구를 분리했다.
- 응답 평가 점수가 낮으면 개선 노드로 다시 보내는 조건부 라우팅을 넣었다.
- 멀티턴 대화 히스토리와 사용자 선호도 누적 구조를 상태로 관리했다.

## 2. project service 관점

### 서비스로서 무엇을 제공하는가
- 뉴스 기반 질의응답
- 실시간 뉴스와 아카이브 뉴스의 혼합 검색
- 날짜 범위 해석
- 응답 품질 자동 평가 및 개선
- 멀티턴 대화와 선호도 반영

### 사용자 가치
- 최신 뉴스만이 아니라 배경 맥락과 아카이브를 함께 반영한 답변을 받을 수 있다.
- 상대적 시간 표현을 직접 날짜로 바꿔 생각하지 않아도 된다.
- 평가-개선 루프 덕분에 단발성 생성보다 더 안정적인 응답 경험을 기대할 수 있다.

### 서비스 구조의 의미
- 단순 RAG 실습을 넘어서, `도구 조합`, `멀티턴`, `품질 평가`, `개선 루프`까지 포함한 서비스형 에이전트 설계를 학습할 수 있다.
- 교육용 프로젝트이지만 실제 뉴스 어시스턴트 구조의 축소판으로 읽을 수 있다.

## 3. 리줌에 쓸 수 있는 포인트
- RAG, 외부 뉴스 API, 날짜 계산 도구를 결합한 LangGraph 뉴스 챗봇 설계
- evaluator-optimizer 패턴을 적용해 응답 품질을 자동 점검하고 개선하는 루프 구현
- 멀티턴 대화와 사용자 선호도 누적을 반영한 상태 기반 에이전트 구현

## 개발자 스토리

저는 성과만 보여주는 사람이 아니라 `왜 그런 결과가 나왔는지 설명하려는 사람`입니다. 교육 영업 현장에서는 운영 구조를 정리해 성과를 확장했고, 브랜드 운영과 창업 현장에서는 상권 제약, 조리 병목, 고객 경험 문제를 직접 다뤘습니다. 여러 번의 창업과 실패를 거치며 감각만으로는 같은 문제를 반복하게 되고, 문제를 구조로 바꾸고 원인을 설명할 수 있어야 다음 개선이 가능하다는 점을 배웠습니다.

AI 전환 이후에는 이 경험을 기반으로 멀티에이전트 분석, RAG, AST 기반 저장소 해석, 운영형 AI 서비스 구조를 구현하고 있습니다. 그래서 제 프로젝트는 단순히 기능을 만드는 데서 끝나지 않고, `왜 이 구조가 필요한지`, `어떤 근거를 남겨야 하는지`, `사용자에게 무엇을 설명할 수 있는지`까지 함께 다룹니다.

자세한 서사는 [개발자 스토리](./developer-story.md)에서 볼 수 있습니다.

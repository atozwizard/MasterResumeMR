# 마스터 리줌 bullet 초안

목적: 저장소 원노트를 직무별 리줌에 바로 넣을 수 있는 bullet 문장으로 압축한다.

## 작성 원칙
- 모든 bullet은 `무엇을 했다`만 쓰지 않고 `왜 그 방식으로 기술문제를 풀었는지`를 포함한다.
- 모든 bullet은 `기술 구현 설명`만 쓰지 않고 `왜 그 문제가 사용자·조직·업무에 중요한지`를 포함한다.
- 한 bullet 안에서 가능하면 `문제 -> 왜 -> 행동 -> 기술 -> 결과` 흐름을 유지한다.
- 수치가 없으면 과장하지 않고 `안정성`, `추적성`, `재사용성`, `운영 가능성`, `의사결정 지원` 같은 결과로 표현한다.

## 1. AI Engineer용 bullet

### 기술문제 해결형
- 분산된 JD, 기술 블로그, 제품 문서, GitHub 저장소를 하나의 분석 흐름으로 묶기 위해 LangGraph 기반 멀티에이전트 파이프라인을 설계했습니다. 서로 다른 근거를 단계별로 분리해 수집해야 분석 결과의 추적성과 재현성이 높아진다고 판단했기 때문입니다.
- 코드 구조와 비즈니스 맥락을 단순 키워드 매칭으로 연결하면 설명력이 약해질 수 있다고 보고, Python AST 정적 분석과 임베딩 기반 유사도 계산을 결합한 코드 분석 구조를 구현했습니다. 어떤 코드가 왜 중요한지 구조적으로 해석할 수 있어야 리포지토리 분석 결과의 신뢰도가 높아지기 때문입니다.
- RAG 기반 유지보수 코치에서 센서 데이터, 유지보수 이력, SOP 문서를 함께 참조하도록 설계했습니다. 단일 데이터 소스만으로는 현장 진단 근거가 부족해 잘못된 조치 제안으로 이어질 수 있다고 판단했기 때문입니다.
- 무역 온보딩 에이전트에서 stale state와 비동기 처리 문제를 수정했습니다. 대화형 에이전트는 단순 응답 품질보다 상태 일관성과 이벤트 루프 안정성이 먼저 확보되어야 실제 업무 교육에 사용할 수 있기 때문입니다.
- 뉴스 챗봇에 evaluator-improver 루프를 도입해 응답을 자동 점검하고 개선하도록 구성했습니다. 검색형 챗봇은 1회 생성 품질보다 반복 개선 가능성이 장기적으로 더 중요하다고 봤기 때문입니다.
- `idol_agent_LUMI`에 LiteLLM fallback, checkpoint, 비용 추적, Langfuse 관측성을 연결했습니다. 서비스형 에이전트는 생성 기능 자체보다 장애 대응, 비용 관리, 추적 가능성이 있어야 운영 가능한 시스템이 되기 때문입니다.

### 비즈니스문제 해결형
- 기업 요구 역량과 사용자 보유 역량을 분리해 분석하는 구조를 설계했습니다. 포트폴리오와 리줌 작성에서는 단순 경험 나열보다 `지원 포지션에 왜 맞는지`를 근거로 설명하는 것이 실제 의사결정에 더 중요하기 때문입니다.
- 무역 온보딩 챗봇에서 리스크 분석, 이메일 초안, 퀴즈 생성 모드를 분리했습니다. 교육 현장에서는 단일 질의응답보다 상황 판단, 문서 작성, 학습 점검까지 이어지는 업무 흐름 지원이 필요하기 때문입니다.
- 제조 유지보수 코치에서 진단, 문서 검색, 추천 조치, 확인 흐름을 연결했습니다. 현장 업무는 정보를 보여주는 것보다 다음 행동을 결정할 수 있게 돕는 것이 더 큰 가치이기 때문입니다.
- 뉴스 챗봇에 메모리와 개인화 흐름을 넣었습니다. 정보 서비스는 정답 한 번보다 사용자의 관심 주제와 이전 대화를 이어가는 경험이 재사용성과 체감 가치를 높이기 때문입니다.
- `idol_agent_LUMI`에 운영 관점 기능을 포함했습니다. 데모용 AI와 운영 가능한 AI의 차이는 가시성, 비용 통제, 복구 가능성에 있으며, 이 요소가 있어야 서비스 지속성이 확보되기 때문입니다.

## 2. Backend Engineer용 bullet

### 기술문제 해결형
- FastAPI 기반 백엔드에서 에이전트 진입점과 실행 책임을 분리했습니다. 에이전트가 늘어날수록 진입 경로와 상태 책임이 섞이면 유지보수 비용이 급격히 증가한다고 판단했기 때문입니다.
- `service_agent` 그래프와 노드를 단계별로 분리해 파일 준비, 기술 추출, 역량 분석, 최종 생성 흐름을 모듈화했습니다. 중간 단계를 분리해야 오류 추적과 후속 개선 지점을 명확히 찾을 수 있기 때문입니다.
- CI와 pre-commit 구성을 정리했습니다. AI 프로젝트에서도 품질 게이트가 자동화되지 않으면 반복적인 포맷·규칙 오류가 누적되어 개발 흐름을 끊기 때문입니다.
- `trade-onboarding-agent`에서 비동기 처리 누락과 동기 호출로 인한 이벤트 루프 블로킹을 수정했습니다. 사용자 체감 성능과 안정성은 모델 품질 이전에 백엔드 처리 구조가 보장해야 하는 기본 조건이기 때문입니다.
- Supabase, PostgreSQL checkpoint, SSE, fallback 구조를 포함한 서비스형 AI 백엔드 패턴을 적용했습니다. 생성형 기능은 응답 생성만으로 끝나지 않고 세션 지속성, 스트리밍, 장애 대응까지 포함해야 실사용 구조가 되기 때문입니다.

### 비즈니스문제 해결형
- 백엔드 구조를 분리하고 실행 경계를 명확히 한 이유는 사용자 경험을 안정적으로 유지하기 위해서였습니다. 상태 꼬임이나 장애 복구 실패는 기능 부족보다 더 빠르게 신뢰를 잃게 만들기 때문입니다.
- CI와 pre-commit 자동화를 강화한 이유는 반복 검수 비용을 줄이기 위해서였습니다. 사소한 규칙 오류를 사람이 계속 잡는 구조는 팀 생산성을 떨어뜨리고 리뷰 집중도를 낮추기 때문입니다.
- 리스크 분석, 문서 작성, 퀴즈 생성 등 기능을 API 단위로 분리한 이유는 실제 업무 흐름과 맞추기 위해서였습니다. 사용자는 모델 자체보다 자신의 업무 단계에 바로 끼워 넣을 수 있는 기능 구성을 더 필요로 하기 때문입니다.
- 스트리밍, 체크포인트, fallback, observability를 포함한 구조를 만든 이유는 운영 중단 비용을 줄이기 위해서였습니다. 서비스형 AI는 한 번의 고품질 응답보다 예측 가능한 운영 경험이 더 중요하기 때문입니다.

## 3. Product Engineer용 bullet

### 기술문제 해결형
- README, 코드 구조, 커밋 근거를 교차 분석해 프로젝트를 다시 문서화했습니다. 문서가 부실한 프로젝트는 구현 역량이 있어도 외부에서 가치를 해석하기 어려워지기 때문에, 설명 가능한 구조로 복원하는 작업이 필요하다고 판단했습니다.
- 프로젝트별 raw note를 문제, 구조, 기술 선택, 기여 근거 중심으로 재구성했습니다. 단순 구현 목록으로는 제품 관점에서 왜 이 기능이 필요한지 전달하기 어렵기 때문입니다.
- 프로젝트 분석 과정에서 근거 파일, 커밋, 출력 구조를 함께 묶었습니다. 설명과 근거가 분리되면 리줌과 포트폴리오, 면접 답변이 서로 다른 이야기로 흩어질 수 있기 때문입니다.

### 비즈니스문제 해결형
- 기업 요구 역량과 사용자 보유 역량을 연결하는 분석 시스템을 만든 이유는 지원자의 포지셔닝 비용을 줄이기 위해서였습니다. 사용자는 무엇을 했는지보다 `왜 자신이 적합한지`를 설명할 수 있어야 실제 지원 성과로 이어지기 때문입니다.
- 무역 온보딩 챗봇에서 실제 업무 흐름에 맞춘 기능 모드를 분리한 이유는 학습 도구를 업무 도구로 전환하기 위해서였습니다. 사용자는 일반적 답변보다 리스크 판단과 문서 작성처럼 바로 적용 가능한 결과를 더 원하기 때문입니다.
- 제조 유지보수 코치에서 진단과 후속 조치를 연결한 이유는 현장 판단 비용을 줄이기 위해서였습니다. 단순 정보 조회는 가치가 제한적이고, 다음 행동을 제안할 때 업무 지원 도구로서 의미가 생기기 때문입니다.
- 뉴스 챗봇에 메모리와 개인화 흐름을 넣은 이유는 재방문 가치를 만들기 위해서였습니다. 정보 서비스는 일회성 정답보다 사용자가 계속 돌아오게 만드는 경험 설계가 더 중요하기 때문입니다.

## 4. 공통 보완 포인트
- 각 bullet에 수치 결과를 추가할 수 있으면 우선 반영한다.
- 각 bullet이 `왜 그렇게 풀었는지`와 `왜 중요한지`를 모두 포함하는지 검토한다.
- 같은 프로젝트에서 기술 관점과 비즈니스 관점이 서로 모순되지 않는지 확인한다.
- 직무별 최종 리줌에서는 5~7개 bullet만 남기고 중복 표현을 제거한다.

## 5. 다음 작업
1. 각 직무별로 최종 선택 bullet 5~7개를 선별한다.
2. 각 bullet에 `성과 근거`, `수치`, `산출물 링크`를 보강한다.
3. 한 페이지용 마스터 리줌 초안으로 다시 압축한다.

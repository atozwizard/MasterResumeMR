# 투트랙 실행계획 2026-03-13

## 목적
마스터 리줌 작성을 위해 다음 단계를 두 갈래로 병렬 진행한다.
- `A트랙`: 프로젝트와 저장소 근거 정제
- `B트랙`: `data/user/yyk` 자료에서 사용자 이력과 메시지 추출

## 공통 원칙
- 모든 산출물은 `기술문제 해결`과 `비즈니스문제 해결` 두 관점으로 읽혀야 한다.
- 두 관점 모두 `무엇`, `왜`, `어떻게`, `결과`를 포함한다.
- 추정은 추정으로 남기고, 근거가 있는 문장만 리줌 후보로 올린다.

## A트랙: 프로젝트

### 목표
- 대표 프로젝트 5~6개를 확정하고, 프로젝트별 핵심 bullet과 근거를 정제한다.

### 실행 순서
1. 우선 프로젝트 5~6개 확정
2. 프로젝트별 핵심 bullet 2개 선별
3. 성과/근거 보강 포인트 정리

### 우선 후보
- `company_analyzer`
- `job-analyzer`
- `trade-onboarding-agent`
- `idol_agent_LUMI`
- `manufacturing-ai-coach`
- 필요 시 `news_chatbot_agent_student`

### 프로젝트별 산출물
- 기술문제 해결형 대표 bullet 1개
- 비즈니스문제 해결형 대표 bullet 1개
- 근거 파일
- 커밋 근거
- 보강이 필요한 수치/산출물

## B트랙: 사용자 자료

### 목표
- `data/user/yyk` 자료들에서 마스터 리줌의 본문 재료를 추출한다.

### 실행 순서
1. 문서 유형 분류
2. 우선 읽기 순서 확정
3. 핵심 정보 추출
4. 중복과 충돌 정리

### 문서 유형
- 이력서
- 포트폴리오
- 자기소개서
- 보조 메모

### 추출 대상
- 기본 정보
- 목표 직무
- 경력/프로젝트
- 기술 스택
- 성과 근거
- 핵심 메시지

## 통합 단계

### 목표
- A트랙의 검증 가능한 프로젝트 근거와 B트랙의 사용자 서술을 합쳐 마스터 리줌 입력값을 만든다.

### 통합 체크포인트
- 대표 프로젝트와 사용자 서술이 서로 일치하는가
- 직무 정체성이 하나의 메시지로 묶이는가
- bullet이 `무엇 -> 왜 -> 어떻게 -> 결과` 흐름을 갖는가
- 같은 경험이 문서마다 다르게 표현된 경우 기준 문장을 정했는가

## 오늘 바로 할 일
1. A트랙 프로젝트 최종 후보 확정
2. B트랙 문서 분류표 작성
3. 우선 읽을 사용자 문서 4~6개 선정
4. 두 트랙의 1차 요약 문서 생성

# A트랙 프로젝트 1차 선별 2026-03-13

## 목적
마스터 리줌에 우선 반영할 프로젝트를 확정하고, 각 프로젝트에서 어떤 관점의 bullet을 먼저 살릴지 정한다.

## 선별 기준
- 기술문제 해결 관점에서 `왜 그 방식으로 풀었는지`를 설명할 수 있는가
- 비즈니스문제 해결 관점에서 `왜 중요한 문제인지`를 설명할 수 있는가
- 본인 기여 근거 파일과 커밋이 충분한가
- AI Engineer / Backend Engineer / Product Engineer 중 2개 이상 직무에서 재사용 가능한가

## 최우선 프로젝트

### 1. `company_analyzer`
- 우선순위: 최상
- 쓰는 이유:
  - 멀티에이전트 구조 설계 경험을 보여주기 좋다
  - 기술문제 해결과 비즈니스문제 해결을 모두 설명하기 좋다
  - `service_agent` 중심 기여 근거가 비교적 선명하다
- 먼저 살릴 bullet:
  - 기술문제 해결형 1개
  - 비즈니스문제 해결형 1개
- 보강 필요:
  - 최종 산출물 예시
  - 분석 결과 활용 방식

### 2. `job-analyzer`
- 우선순위: 최상
- 쓰는 이유:
  - AST + 임베딩 결합이라는 분석 구조의 이유를 설명하기 좋다
  - 코드와 비즈니스 가치를 연결하려는 관점이 분명하다
  - 초기 핵심 구현 기여 범위가 넓다
- 먼저 살릴 bullet:
  - 기술문제 해결형 1개
  - 비즈니스문제 해결형 1개
- 보강 필요:
  - 실제 출력 예시
  - 외부 정보 수집 흐름의 결과

### 3. `trade-onboarding-agent`
- 우선순위: 상
- 쓰는 이유:
  - 비동기 처리, stale state, 멀티모드 설계 등 백엔드 안정화 포인트가 있다
  - 교육/실무 지원이라는 비즈니스 문제도 뚜렷하다
- 먼저 살릴 bullet:
  - 백엔드 안정화 bullet 1개
  - 업무 흐름 지원 bullet 1개
- 보강 필요:
  - 테스트 결과
  - 사용자 시나리오

### 4. `idol_agent_LUMI`
- 우선순위: 상
- 쓰는 이유:
  - fallback, checkpoint, 비용 추적, observability 등 운영형 AI 포인트가 선명하다
  - 데모형이 아니라 운영 가능한 구조라는 메시지를 주기 좋다
- 먼저 살릴 bullet:
  - 운영성 확보 bullet 1개
  - 사용자 신뢰/지속사용 가치 bullet 1개
- 보강 필요:
  - 실제 운영 또는 데모 흐름
  - 세션 지속성과 비용 관리 결과

### 5. `manufacturing-ai-coach`
- 우선순위: 상
- 쓰는 이유:
  - RAG와 현장 데이터를 함께 묶는 구조를 설명하기 좋다
  - 문제 정의가 실무와 직결되어 Product 관점까지 확장 가능하다
- 먼저 살릴 bullet:
  - 복합 데이터 진단 구조 bullet 1개
  - 유지보수 의사결정 지원 bullet 1개
- 보강 필요:
  - 현장 시나리오
  - 추천 조치 흐름 예시

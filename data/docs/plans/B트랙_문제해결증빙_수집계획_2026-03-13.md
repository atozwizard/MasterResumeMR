# B트랙 문제해결증빙 수집계획 2026-03-13

## 목적
`커피소녀오즈`, `우동오즈`, `쿤타치 자가제면`, `리틀방콕` 등 사용자의 브랜드/경력 경험에서 `어떤 문제를 어떻게 해결했는지`를 설명할 수 있도록, 현재 사용자 데이터가 전부라고 가정한 상태에서 추가 수집 계획을 정리한다.

## 전제
- 현재 `data/user/yyk`에 있는 자료가 사용자가 제공한 전부라고 가정한다.
- 사업자등록번호, 폐업정보, 회계자료, POS 원장 등 직접 증빙은 아직 확보되지 않은 상태로 본다.
- 따라서 당분간은 `사용자 문서 + 공개 검색 자료`를 결합해 문제 해결 서사의 근거를 최대한 보강해야 한다.

## 왜 추가 수집이 필요한가
- 현재는 브랜드 존재 흔적과 일부 시점 단서만 있고, `문제 -> 조치 -> 결과`를 입증할 데이터가 부족하다.
- 특히 정량 데이터만으로는 브랜드 운영의 맥락이 약하므로, 이용자 후기와 블로그 글에서 읽히는 정성 데이터도 같이 모아야 한다.
- 특히 아래 항목이 약하다.
  - 문제의 구체성
  - 당시 상황의 맥락
  - 조치 전후 변화
  - 숫자로 표현 가능한 결과
  - 그 결과가 왜 비즈니스적으로 중요했는지 보여주는 단서

## 수집 목표

### 1. 브랜드별 문제 정의 보강
- 어떤 운영 문제가 있었는가
- 고객이 실제로 무엇에 불편을 느꼈는가
- 상권, 입지, 피크타임, 상품 구조 중 어디가 병목이었는가

### 2. 문제 해결 행동 보강
- 어떤 메뉴 변경, 프로세스 변경, 동선 변경, 브랜딩 조정, 타겟 조정이 있었는가
- 사용자가 직접 한 일이 무엇이었는가

### 3. 결과 보강
- 매출 변화
- 회전율 변화
- 대기시간/서빙시간 변화
- 객단가 변화
- 재방문/단골/납품 계약 변화
- 운영 안정성/표준화/CS 감소

## 수집 우선순위

### 최우선
- 네이버 플레이스/블로그 기반 브랜드 흔적
- 메뉴, 상권, 위치, 운영 시간, 리뷰 키워드
- 실제 이용자가 남긴 후기의 반복 표현
  - 친절
  - 분위기
  - 대기
  - 회전
  - 양
  - 시그니처 메뉴
  - 재방문
- 포트폴리오와 자기소개서 안의 문제 해결 진술

### 2순위
- 언론, 리뷰, 집계 사이트, 업체 소개 페이지
- 브랜드명 + 지역명 + 키워드 검색 결과
  - `대기`
  - `줄`
  - `점심`
  - `자가제면`
  - `신메뉴`
  - `브랜딩`
  - `납품`

### 3순위
- 사업장 흔적, 인허가, 폐업 집계
- 외부 블로그 후기와 SNS 포스팅

## 브랜드별 수집 전략

### 1. 커피소녀오즈

#### 수집할 것
- 브랜드 소개 문구
- 어떤 고객층을 대상으로 했는지
- 납품, 원두, 브랜딩, 메뉴, 공간 관련 단서
- B2B 계약/고객 맞춤 전략과 연결 가능한 공개 흔적
- 리뷰에 반복적으로 등장하는 메뉴/경험 키워드
  - 샌드위치
  - 시그니처 음료
  - 공간 경험

#### 만들고 싶은 문제 해결 문장
- 고객 페르소나에 따라 공급 전략을 바꾸어 장기 계약으로 이어졌는가
- 브랜딩과 마케팅을 직접 설계해 어떤 차별화를 만들었는가

### 2. 우동오즈 / 쿤타치 자가제면

#### 수집할 것
- 위치와 상권 특성
- 점심 피크 시간, 대기, 회전율, 메뉴 구성 관련 리뷰/블로그 단서
- 자가제면, 조리시간, 서빙시간, 신메뉴, 좌석/동선 관련 설명
- `구 리틀방콕 자리` 단서를 포함한 공간 전환 맥락
- 운영시간 단서
- 점심 집중형 영업 여부

#### 만들고 싶은 문제 해결 문장
- 조리시간이 긴 구조를 어떻게 단축했는가
- 상권 특성과 점심 시간 제약에 맞춰 메뉴/운영을 어떻게 바꿨는가
- 데이터화와 공정 분석이 어떻게 비즈니스 문제 해결로 이어졌는가

### 3. 리틀방콕

#### 수집할 것
- 매장 규모, 업종, 위치 단서
- HR, CS, 유통 구조 경험과 연결 가능한 운영 정보
- `구 리틀방콕 자리`와 브랜드 전환 맥락

#### 만들고 싶은 문제 해결 문장
- 운영 체계화와 교육 매뉴얼 정리가 어떤 문제를 줄였는가
- 프랜차이즈 운영 구조 경험이 이후 브랜드 운영에 어떻게 연결되었는가

## 자료 유형별 수집 항목

- 상호

- 메뉴

- 대기/혼잡/회전율 단서
- 메뉴/서비스 강약점
- 시기 정보
- 재방문 의사
- 공간 분위기와 동선 체감
- 친절/응대 품질
- 시그니처 메뉴 인식

### 사용자 문서
- 이미 서술한 문제 해결 사례
- 정량 수치
- 브랜드 전환 맥락
- 운영 의사결정 배경

## 현실적인 한계
- 공개 자료만으로 실제 매출 수치를 복원하는 것은 어렵다.
- 따라서 매출이 없으면 운영 지표와 고객 반응 단서로 우회해야 한다.
- 강한 숫자가 없을 경우에도 아래는 충분히 쓸 수 있다.
  - 서빙 시간
  - 대기 감소
  - 회전율
  - 수업 수 증가
  - 계약 성사
  - 고객층 전환
  - 메뉴 전환 효과

## 실행 순서
1. 브랜드별 기존 사용자 진술 수집
2. 네이버/블로그/업체 정보 기반 공개 단서 수집
3. 문제 해결 서술 후보 작성
4. 숫자와 보조 근거 분리
5. 마스터 리줌 원재료집에 반영

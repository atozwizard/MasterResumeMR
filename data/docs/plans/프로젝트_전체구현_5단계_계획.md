# 마스터 리줌 자동화 프로젝트 전체 구현 5단계 계획

## 목적
자기소개서, 프로젝트 문서, GitHub 저장소, README, 커밋 로그를 수집·분석해 `마스터 리줌`과 `직무별 맞춤 리줌`을 자동 생성하는 시스템을 설계한다.

## 범위
- 입력
  - `data/` 아래의 자기소개서, 이력서, PDF, 메모 문서
  - `repo/` 아래의 프로젝트 저장소
  - 저장소의 `README`, 코드 구조, 설정 파일, 커밋 로그
- 출력
  - 마스터 리줌 원본
  - 직무별 압축 리줌
  - 프로젝트별 원노트
  - 기여 근거 노트
  - 로그와 진행 문서

## 핵심 원칙
- 모든 프로젝트는 `기술문제 해결`과 `비즈니스문제 해결` 두 관점으로 동시에 정리한다.
- 두 관점 모두 `무엇을 했다`에서 끝나지 않고 `왜 그렇게 풀었는지`까지 남긴다.
- 기술 관점에서는 `왜 그 기술, 구조, 흐름을 선택했는가`를 설명한다.
- 비즈니스 관점에서는 `왜 그 문제가 사용자·조직·업무에 중요한가`를 설명한다.
- 최종 bullet은 가능하면 `문제 -> 왜 -> 행동 -> 기술 -> 결과` 흐름으로 작성한다.

## Phase 1. 자료 인벤토리 정리

### 목표
- 원본 자료의 위치, 형식, 메타데이터를 정리한다.

### 구현 항목
- `data/` 문서 인덱싱
- `repo/` 저장소 인덱싱
- 파일 유형 분류
  - Markdown / TXT
  - PDF
  - `README`, `pyproject.toml`, `package.json`, `.env.example`
- 문서와 저장소 간 연결 태그 생성

### 산출물
- 자료 인벤토리
- 저장소 인벤토리
- 입력 소스별 태그 목록

### 종료 조건
- 어떤 자료가 어디에 있고 무엇을 설명하는지 추적 가능해야 한다.

## Phase 2. 저장소 분석 자동화

### 목표
- 프로젝트 목적, 구조, 사용 기술, 기여 근거, 결과 해석 요소를 자동 추출한다.

### 구현 항목
- README 품질 진단
- 코드 구조 분석
  - 엔트리포인트 추출
  - 핵심 디렉터리 추출
  - 에이전트, API, 프론트엔드, 백엔드 구분
- 의존성 분석
  - `pyproject.toml`
  - `requirements.txt`
  - `package.json`
- 커밋 기여 분석
  - 작성자 기준 커밋
  - 파일 변경 빈도
  - 기능성 커밋 추출
- 기술문제 해결 이유 추출
  - 왜 해당 구조를 선택했는가
  - 왜 해당 기술을 선택했는가
  - 왜 그 흐름이 필요했는가
- 비즈니스문제 해결 이유 추출
  - 왜 사용자와 조직에 중요한가
  - 어떤 업무 비효율이나 의사결정 문제를 줄이는가

### 산출물
- 프로젝트 원노트
- README 감사 문서
- 기여 근거 파일 목록
- 기술문제 해결 노트
- 비즈니스문제 해결 노트

### 종료 조건
- 각 저장소를 두 관점으로 설명할 수 있어야 한다.

## Phase 3. 증거 그래프 생성

### 목표
- 프로젝트, 기술, 역할, 문제, 결과를 하나의 근거 그래프로 연결한다.

### 구현 항목
- 엔티티 추출
  - 프로젝트명
  - 역할
  - 기술 스택
  - 문제
  - 결과
- 이유 추출
  - 기술 선택 이유
  - 구조 선택 이유
  - 비즈니스 중요성 이유
- 관계 생성
  - `프로젝트 -> 기술`
  - `프로젝트 -> 문제`
  - `프로젝트 -> 결과`
  - `직무 -> 적합 프로젝트`
- evidence pack 생성
  - 리줌용 근거 문장
  - 면접용 근거 문장

### 산출물
- 프로젝트-기술-문제-결과 매핑 그래프
- 직무별 추천 프로젝트 노트

### 종료 조건
- 특정 직무를 넣으면 관련 프로젝트와 근거 문장이 자동 선택되어야 한다.

## Phase 4. 리줌 생성 자동화

### 목표
- 마스터 리줌과 직무별 리줌을 자동 생성한다.

### 구현 항목
- 마스터 리줌 생성기
  - 전체 경력, 프로젝트, 학습 이력 포함
- 직무별 필터
  - `AI Engineer`
  - `Backend Engineer`
  - `Product Engineer`
- bullet 생성기
  - 문제
  - 왜
  - 행동
  - 기술
  - 결과
- 관점별 bullet 생성기
  - 기술문제 해결형 bullet
  - 비즈니스문제 해결형 bullet

### 산출물
- 마스터 리줌 초안
- 직무별 리줌 버전
- 프로젝트 소개문

### 종료 조건
- 사용자가 목표 직무를 지정하면 제출 가능한 초안이 생성되어야 한다.

## Phase 5. 운영 자동화와 품질 관리

### 목표
- 자료 갱신, 저장소 변경 추적, 문서 최신성 유지를 자동화한다.

### 구현 항목
- 변경 감지
  - 새 문서 추가
  - 저장소 업데이트
  - 커밋 로그 변경
- 자동 로그 갱신
- 리줌 재생성 트리거
- 품질 점검
  - 중복 bullet 감지
  - 근거 없는 문장 감지
  - 직무 적합성 점검
  - `왜`가 빠진 bullet 감지

### 산출물
- 운영 워크플로
- 품질 체크리스트
- 재생성 이력 로그

### 종료 조건
- 새 자료가 들어오면 리줌 원본과 직무별 결과가 일관되게 갱신되어야 한다.

# 마스터 리줌 관점별 제안

## 목적
참조 문서에 반영된 기준을 바탕으로, 실제 리줌 작성 단계에서 어떤 순서로 압축할지 제안한다.

## 제안 원칙
- 각 프로젝트는 `기술문제 해결형 1개`와 `비즈니스문제 해결형 1개`를 기본 단위로 잡는다.
- 두 문장은 서로 다른 말을 해야 하지만, 같은 프로젝트의 맥락을 공유해야 한다.
- 최종 리줌에서는 직무별로 5~7개 bullet만 남긴다.

## 직무별 선별 제안

### AI Engineer
- 우선 사용 프로젝트
  - `company_analyzer`
  - `job-analyzer`
  - `idol_agent_LUMI`
  - `manufacturing-ai-coach`
  - `news_chatbot_agent_student`
- 선별 기준
  - 에이전트 구조 설계 경험
  - RAG 또는 검색 결합 경험
  - 평가, fallback, observability 같은 운영 요소
  - 기술 선택 이유를 설명할 수 있는가

### Backend Engineer
- 우선 사용 프로젝트
  - `company_analyzer`
  - `trade-onboarding-agent`
  - `idol_agent_LUMI`
  - `manufacturing-ai-coach`
- 선별 기준
  - FastAPI 구조화 경험
  - 비동기 처리, 상태 관리, 스트리밍, 체크포인트
  - CI와 품질 게이트
  - 안정성과 운영성에 대한 설명 가능성

### Product Engineer
- 우선 사용 프로젝트
  - `company_analyzer`
  - `trade-onboarding-agent`
  - `manufacturing-ai-coach`
  - `news_chatbot_agent_student`
- 선별 기준
  - 사용자의 실제 문제를 어떻게 정의했는가
  - 기능을 업무 흐름 단위로 어떻게 나눴는가
  - 정보 제공을 넘어 행동과 의사결정을 어떻게 지원했는가

## 다음 작성 순서
1. 프로젝트별로 `기술문제 해결형`과 `비즈니스문제 해결형` 대표 문장을 각각 1개씩 뽑는다.
2. 직무별로 중복 프로젝트를 제거하고 5~7개 bullet만 남긴다.
3. 각 bullet에 수치, 산출물, 근거 파일을 덧붙인다.
4. 마지막에 한 줄 핵심 메시지를 붙여 리줌 전체 방향을 고정한다.

## 추천 핵심 메시지 초안
- 현장의 문제를 기술 구조로 풀고, 그 결과를 사용자와 조직의 가치 언어로 다시 설명할 수 있는 AI/백엔드 엔지니어

## 바로 이어서 할 일
1. `AI Engineer` 최종 선별안 작성
2. `Backend Engineer` 최종 선별안 작성
3. `Product Engineer` 최종 선별안 작성

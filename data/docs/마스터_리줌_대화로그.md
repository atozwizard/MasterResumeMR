# 마스터 리줌 대화로그

## 2026-03-12 주요 대화 요약

### 1. 목표 설정
- 마스터 리줌 작성을 목표로 설정했다.
- 우선순위는 `재료 수집 -> 저장소 근거 확보 -> 원노트 작성 -> 직무별 bullet 압축`으로 정했다.

### 2. 자료 수집 방식 결정
- `data/` 폴더만으로는 raw data가 부족하다고 판단했다.
- `atozwizard` 계정의 비포크 저장소를 모두 수집하고, 별도 지정 저장소도 클론하기로 했다.
- 추가로 `company_analyzer`의 `dev`, `programmers-high-score-kit`의 `main` 브랜치를 클론했다.

### 3. README 처리 원칙 결정
- README가 충분하면 보조 자료로 사용한다.
- README가 약하면 코드 구조, 설정 파일, 커밋, 산출물 기준으로 프로젝트를 재구성한다.
- 문서 공백이 크면 README를 직접 작성하거나 보강한다.

### 4. 로그와 진행 문서 체계 결정
- `data/logs/` 아래에 날짜별 대화로그와 진행현황 파일을 관리한다.
- 날짜가 바뀌면 새 파일을 생성하고, 같은 날짜면 활성 파일에 계속 누적한다.

### 5. 리줌 작성 방식 결정
- 저장소 raw note를 바탕으로 직무별 bullet 초안을 만든다.
- 직무는 `AI Engineer`, `Backend Engineer`, `Product Engineer` 기준으로 나눈다.

### 6. 검토 결과와 기준 강화
- 기존 문서는 `무엇을 했다`는 정리되었지만 `왜 그렇게 풀었는지`가 약하다고 판단했다.
- 특히 `problem solve` 관점에서도 기술 선택의 이유가 부족하고, `business solve` 관점에서도 왜 중요한지 설명이 약했다.
- 이에 따라 모든 참조 문서에서 아래 두 관점을 동시에 강제하기로 했다.
  - `기술문제 해결`: 왜 그 구조와 기술을 선택했는가
  - `비즈니스문제 해결`: 왜 그 문제가 사용자·조직·업무에 중요한가

### 7. 이번 턴에서 반영한 내용
- 자료수집 템플릿 수정
- 5단계 구현 계획 수정
- 자동화 코드 아키텍처 설계 수정
- 저장소 원노트 수정
- 직무별 bullet 초안 수정
- 관점별 제안 문서 추가

### 8. 현재 다음 단계

# Product_Engineer_본문초안_1차

## 핵심 메시지
고객 경험과 운영 문제를 읽고, 이를 제품 구조와 AI 도구로 전환해 설명 가능한 형태로 만드는 Product Engineer 지향 인재.

## 프로필
브랜드 운영, 프랜차이즈 경험, 교육 현장 성과, AI 프로젝트 구현 경험을 연결해 `문제 정의 -> 구조 설계 -> 구현` 흐름으로 문제를 풀어 왔다.

## 경력 요약
- 고객 페르소나에 맞춘 공급 전략과 브랜딩, 제품 경험 설계를 직접 주도했다.
- 장기 거래와 반복 방문 기반을 만드는 브랜드 운영을 경험했다.
- 프랜차이즈 매장에서 서비스와 운영 완성도가 재방문 경험에 연결된다는 점을 현장에서 배웠다.
- 운영 구조와 실행 방식을 정비해 관리 수업 수를 안정적으로 확대했고, 성장률과 운영 성과를 연결하는 방식으로 문제를 해결했다.
- 공개 저장소와 프로젝트를 기반으로 AI Agent, RAG, 분석 도구를 지속적으로 구현하고 있다.

## 대표 프로젝트

### company_analyzer
- 기업 요구 역량과 사용자 보유 역량을 분리 분석한 뒤 연결하는 흐름을 설계해, 적합성을 설명 가능한 형태로 구조화했다.
- 분산된 JD, 기술 블로그, 제품 문서, GitHub 저장소를 하나의 분석 흐름으로 묶으면서도 결과 출처를 추적할 수 있도록 설계했다.

### job-analyzer
- JD 분석, 저장소 분석, 외부 정보 수집을 묶어 기술 경험을 업무 가치 언어로 번역하는 흐름을 만들었다.
- Python AST 정적 분석과 임베딩 기반 유사도 계산을 결합해 코드 구조와 역할까지 해석하는 저장소 분석 구조를 구현했다.

### manufacturing-ai-coach
- 진단, 문서 검색, 추천 조치, 확인 흐름을 연결해 유지보수 의사결정 보조 도구로 설명 가능한 구조를 만들었다.
- 센서 데이터, 유지보수 이력, SOP 문서를 함께 참조하는 RAG 기반 복합 데이터 진단 구조를 설계했다.

## 기술 스택
- Python, SQL
- RAG, Prompt Engineering, MCP
- FastAPI, Docker
- Web Crawling, OCR

## 강점
- 고객과 운영 문제를 먼저 읽고 구조화함
- 기술 구현을 사용자 가치와 조직 가치로 다시 설명할 수 있음
- 재방문, 적합성 설명, 운영 완성도 관점이 강함

## 보강 필요
- 브랜드별 정확한 운영 기간과 역할
- 프로젝트별 수치 성과
- 직접 증빙 파일 연결

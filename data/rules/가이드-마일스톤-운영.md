# 마일스톤 운영 가이드

## 목적

GitHub milestone을 현재 프로젝트의 실제 작업 흐름에 맞게 관리하기 위한 기준입니다.
이 저장소에서는 과거 멀티에이전트 제품 개발용 milestone 체계가 아니라, `마스터 리줌 구축 작업`에 맞는 phase 중심 milestone을 사용합니다.

## 운영 원칙

- milestone 이름은 `완료해야 할 결과`를 기준으로 정합니다.
- milestone은 현재 프로젝트의 단계와 직접 연결되어야 합니다.
- 새 milestone은 꼭 필요한 최소 개수만 만듭니다.
- 로컬 계획 문서와 GitHub milestone 이름은 가능한 한 일치시킵니다.

## 권장 체계

### Phase milestone
- `phase1-자료인벤토리-정리`
- `phase2-저장소분석-정리`
- `phase3-증거그래프-정리`
- `phase4-리줌초안-작성`
- `phase5-운영자동화-정리`

### 트랙 milestone
- 필요 시 아래 2개를 보조 milestone 또는 설명 단위로 사용합니다.
  - `track-a-프로젝트근거-정제`
  - `track-b-사용자자료-추출`

## 현재 저장소에서의 선택 기준

### phase milestone을 우선 쓰는 경우
- 장기 계획과 전체 진행률을 관리할 때
- 여러 문서와 작업이 같은 단계 목표를 공유할 때

### 트랙 milestone을 보조로 쓰는 경우
- A트랙과 B트랙을 나눠 병렬 진행할 때
- phase 안에서 어떤 축의 작업인지 구분이 필요할 때

## 피해야 하는 이름

- `phase-1`
- `docs`
- `resume`
- `misc`
- `test`

이름만 보고 목표를 알 수 없는 milestone은 사용하지 않습니다.

## GitHub 설정 권장안

초기에는 아래 5개만 생성합니다.

1. `phase1-자료인벤토리-정리`
2. `phase2-저장소분석-정리`
3. `phase3-증거그래프-정리`
4. `phase4-리줌초안-작성`
5. `phase5-운영자동화-정리`

## 체크리스트

- [ ] milestone 이름만 보고 목표가 드러나는가
- [ ] 로컬 계획 문서와 이름이 충돌하지 않는가
- [ ] 현재 프로젝트 문맥과 무관한 과거 체계가 섞여 있지 않은가

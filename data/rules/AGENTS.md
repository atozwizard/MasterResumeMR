# AGENTS.md

이 문서는 `MasterResumeMR` 프로젝트에서 작업을 시작할 때 가장 먼저 확인해야 하는 공용 진입점입니다.
이 저장소의 목적은 `프로젝트 근거`와 `사용자 문서`를 수집·정리해 마스터 리줌과 직무별 리줌 초안을 만드는 것입니다.

## 적용 범위

- 저장소 전체(`.`)에 적용합니다.
- 문서 작성, 계획 수립, 로그 기록, GitHub 메타데이터 정리 작업에 공통 적용합니다.

## 작업 시작 순서

1. 요청을 `A트랙`, `B트랙`, `운영/메타데이터`, `문서 규칙` 중 어떤 유형인지 분류합니다.
2. `data/rules/README.md`를 먼저 확인해 해당 작업의 기준 문서를 선택합니다.
3. 선택한 문서의 체크리스트와 운영 규칙을 따라 작업합니다.
4. 완료 전에는 범위 이탈, 경로 누락, 로그 반영 여부를 확인합니다.

## 문서 운영 원칙

- 규칙 문서의 단일 진입점은 `data/rules/README.md`입니다.
- 문서 추가/이동/이름 변경 시 `data/rules/README.md` 인덱스를 함께 갱신합니다.
- 계획 문서는 `data/docs/plans/`에 저장합니다.
- 진행 기록은 `data/logs/`에 날짜별 파일로 저장합니다.
- 사용자 원본 자료는 `data/user/` 아래에서 관리합니다.

## 우선 참조 문서

### 문서 인덱스
- 파일: `data/rules/README.md`
- 역할: 규칙 문서를 찾기 위한 단일 진입점

### README 작성 가이드
- 파일: `data/rules/가이드-리드미-작성.md`
- 역할: 루트 README 또는 하위 문서형 README를 작성할 때의 기준

### 마일스톤 운영 가이드
- 파일: `data/rules/가이드-마일스톤-운영.md`
- 역할: GitHub milestone 구조와 사용 기준 정의

### 프로젝트 루트 구조 가이드
- 파일: `data/rules/가이드-프로젝트-루트-디렉토리-구조.md`
- 역할: 현재 저장소의 디렉터리 역할과 배치 기준 정의

### 브랜치 운영 규칙
- 파일: `data/rules/규칙-브랜치-운영.md`
- 역할: `main`, `dev`, `feat/*`, `fix/*`, `etc/*`의 사용 기준

### 이슈 생성 절차
- 파일: `data/rules/절차-에이전트-이슈-생성.md`
- 역할: GitHub issue 생성 전 확인 항목과 절차 정의

## 현재 프로젝트 기준

### A트랙
- 프로젝트/저장소 분석
- 대표 프로젝트 선별
- 기술문제 해결형 / 비즈니스문제 해결형 bullet 정리

### B트랙
- `data/user/yyk` 자료 분류
- 기본 정보, 경력, 성과, 메시지 추출
- 마스터 리줌 본문 재료 정리

### 운영
- 로그 문서 관리
- GitHub 저장소 메타데이터 정리
- milestone, label, description, topic 관리

## 작업 원칙

- 기본 응답 언어는 한국어입니다.
- 모든 핵심 문장은 `무엇`, `왜`, `어떻게`, `결과` 중 최소 3개 이상을 담도록 정리합니다.
- 마스터 리줌 관련 문서는 `기술문제 해결`과 `비즈니스문제 해결` 두 관점을 함께 유지합니다.
- 추정은 추정으로 명시하고, 근거가 없는 성과 표현은 쓰지 않습니다.

## 브랜치와 메타데이터 원칙

- 기본 브랜치는 `main`입니다.
- 문서/운영 작업은 필요 시 `etc/*` 브랜치를 사용할 수 있습니다.
- GitHub milestone은 현재 프로젝트의 phase 또는 트랙 기준으로 운영합니다.
- 레거시 브랜치(`main_old`, `dev_old`) 기준은 이 저장소의 기본 운영 규칙이 아닙니다.

## 완료 전 체크

- 요청 범위를 벗어난 변경이 없는가
- `data/rules/README.md` 인덱스가 최신인가
- 관련 계획 문서와 로그가 필요한 만큼 반영되었는가
- GitHub 메타데이터 변경이 있다면 로컬 문서와 일치하는가

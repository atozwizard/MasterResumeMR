# README 작성 가이드

이 문서는 현재 저장소와 하위 작업 문서에 일관된 README 또는 개요 문서를 작성하기 위한 기준입니다.

## 대상

- 저장소 루트 README (`README.md`)
- 규칙/계획/원노트 디렉터리의 안내 문서
- 필요 시 하위 프로젝트 설명 문서

## 공통 원칙

- 문서는 한국어로 작성합니다.
- 첫 문단에서 `무엇을 위한 문서인지`를 1~2문장으로 분명히 설명합니다.
- 실제 경로, 실제 문서명, 실제 실행 순서를 기준으로 씁니다.
- 구현되지 않은 내용은 현재 상태와 확장 계획을 구분해 적습니다.
- 흐름 설명이 중요하면 `mermaid` 다이어그램을 사용할 수 있습니다.

## 현재 프로젝트 기준으로 README에 들어가야 할 것

### 루트 README
1. 프로젝트 목적
2. 현재 운영 방식
3. 주요 디렉터리 설명
4. 작업 흐름
5. 문서 위치
6. GitHub 운영 기준

### 디렉터리용 안내 문서
1. 디렉터리 목적
2. 어떤 종류의 문서가 있는지
3. 문서를 읽는 순서
4. 갱신 규칙

## 현재 저장소에서 자주 설명해야 하는 구조

- `data/docs/`
  - 마스터 리줌 재료, 원노트, bullet 초안
- `data/docs/plans/`
  - 실행 계획과 단계별 선별 문서
- `data/logs/`
  - 날짜별 대화로그와 진행현황
- `data/user/`
  - 사용자 원본 자료
- `repo/`
  - 프로젝트 근거 확보용 클론 저장소
- `data/rules/`
  - 운영 규칙과 가이드

## 체크리스트

- [ ] 문서 목적이 첫 문단에 드러나는가
- [ ] 현재 저장소 구조와 경로가 정확한가
- [ ] 과거 프로젝트 예시가 현재 프로젝트 설명을 덮고 있지 않은가
- [ ] 계획과 현재 상태가 구분되어 있는가
